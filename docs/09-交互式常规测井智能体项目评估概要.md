# 交互式常规测井智能体项目评估概要

> 日期：2026-10-06  
> 状态：评估建议，尚未执行  
> 依据：[产品需求概要](./07-交互式常规测井智能体产品需求文档.md)和[项目目标概要](./08-交互式常规测井智能体项目目标概要.md)。

## 一、评估原则

按项目目标分别评估交互、实际执行和专业结果。每项结论需要对应测试记录。

对话回复不能单独证明任务成功。模拟接口可以验证交互，不能证明真实算法结果。

## 二、评估内容

| 目标 | 验证方法 | 通过依据 |
|---|---|---|
| 理解井与资料 | 使用不同资料和缺失资料样本 | 井与曲线信息正确，系列识别和流程推荐符合专家确认规则。 |
| 自然语言控制 | 对同一操作使用不同表达，并加入含糊指令 | 实际操作、目标层段和采用参数正确。对象不明确时先澄清。 |
| 真实业务闭环 | 使用脱敏测试井完成处理解释 | 各环节实际执行，产物完整，专业结果符合约定参考标准。 |
| 持续迭代 | 连续调整层段参数和处理模型 | 上下文正确，重处理符合计算依赖，前后结果可核对。 |
| 工作台联动 | 执行操作、定位节点并查看专业图表 | 模块、状态和结果一致，页面及时更新。更新时延门槛待确定。 |
| 结果可信 | 测试非法参数、执行失败和旧任务迟到 | 非法操作被拦截，错误可查，有效结果未被错误覆盖。 |

## 三、评估步骤

1. 准备脱敏样本、预期操作和专家参考结果。
2. 验证自然语言、模块调用和页面联动。
3. 接入真实业务模块，验证完整处理与连续迭代。
4. 测试资料缺失、非法参数、执行失败等异常。
5. 汇总结果、限制和需要改进的事项。

一口测试井可以验证首版闭环。扩大生产适用范围时，需要补充不同资料和业务场景。

## 四、指标与证据

建议记录下列指标：

- 操作正确率：操作、对象和参数均正确的请求占比。
- 任务完成率：取得约定有效产物的任务占比。
- 专业结果差异：实际结果与专家参考结果的差异。
- 响应与执行时间：指令响应、业务计算和页面更新的耗时。
- 异常处理结果：是否拦截非法操作并保护有效结果。

每项记录包含用户指令、实际调用、采用参数、执行状态和输出结果。评估人员根据记录作出判断。

专业判定标准应在专业测试前确定。性能指标先测基线，再约定验收门槛。正式验收采用已确定的标准。

## 五、评估结论

每个目标分别标记为“通过”“未通过”“受限”或“未评估”。受限项需要说明原因和实际支持范围。

首版建议以真实闭环、连续调整、页面联动和结果保护作为完成依据。模拟验证、未知规则和未评估项不能计为通过。

错误处理对象、无依据的正式结果或有效结果被错误覆盖，属于关键失败。关键失败修复并复测前，不判定首版完成。
