# 交互式常规测井智能体产品需求概要

> 日期：2026-10-06  
> 状态：待评审  
> 依据：用户提供的《09-03晨会》纪要及本次确认的产品方向。

## 一、产品定位

建设面向单井常规测井的交互式生产工具。系统先认识井和资料，再推荐适用流程。

用户通过自然语言和业务页面控制处理过程。用户可以围绕指定层段反复调整参数、切换方法和重新处理。执行结果反馈到对应业务页面。

## 二、核心需求

下列能力来自晨会纪要。

| 需求 | 概要说明 |
|---|---|
| 井与资料认知 | 展示井型、井别、位置、测量系列、装备和已有曲线。说明曲线含义。 |
| 流程识别与推荐 | 根据实际数据识别测量系列，推荐适用处理流程。 |
| 自然语言控制 | 支持流程跳转、重新执行指定步骤、调整参数和选择处理模型。 |
| 层段持续迭代 | 支持对指定层段反复处理。完整流程结束后仍可继续操作。 |
| 统一业务能力 | 核心模块提供可调用能力。明确指令、参数、结果和通信方式。 |
| 动态工作台 | 按模块配置业务页面。联动流程节点、智能体、专业图表和处理结果。 |
| 专业数据检查 | 使用统计、交汇图、骨架位置和地质先验判断质量。发现异常后支持校正。 |
| 结果分析与报告 | 在工作台完成结果分析，并支持报告浏览、编辑和下载。 |

纪要建议各阶段页面自上而下组合。点击节点可以定位页面。滚动页面时激活对应节点。

## 三、业务流程

完整处理采用会议建议的路径：

```text
井信息分析 → 测量系列识别 → 数据解编 → 数据统计分析
→ 数据检查 → 数据预处理 → 智能处理 → 结果分析 → 解释报告
```

后续操作根据用户要求选择相关步骤。具体执行需要满足专业前置条件。

典型指令包括：

- “重新做一下深度校正。”
- “调整这个层段的参数后重新处理。”
- “使用区域机理模型重新解释。”

## 四、支撑能力建议

为支持持续交互，建议补充以下能力：

- 保持当前井、层段和操作对象的上下文。
- 校验参数，并确定修改后的计算影响范围。
- 保留处理记录和结果来源，支持前后比较。
- 显示真实执行状态和错误，保护已有有效结果。

这些条目属于设计建议。具体业务规则需要确认。

## 五、首版范围建议

首版聚焦单井常规测井。先验证“认识资料—检查处理—形成解释—层段调整—重新处理—更新结果与报告”的闭环。

识别成像、微扫资料与执行其专用流程需要分别确定范围。通信协议和技术框架另行评估。

## 六、待确认事项

- 报告模板、编辑内容和更新方式。
