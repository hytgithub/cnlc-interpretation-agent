# 常规测井解释

## 使用范围

用户要求完整解释或按步骤推进时，使用本 Skill。单项资料和已有层段结果按资料查看 Skill 查询；参数调整及指定步骤重跑按处理调整 Skill 执行，不自动运行整套流程。

开始前确定执行模式：

- **整套流程**：用户说“完整解释”“全部跑完”等时，按下表顺序连续执行。每一步都检查实际结果和继续条件，再决定是否执行下一步。
- **逐步执行**：用户说“一步一步”“逐步跑”等时，每次只执行一个处理阶段。阶段完成后汇报实际结果、告警和建议的下一阶段，然后暂停，等用户明确要求继续。用户说“继续”后，只执行下一阶段。
- **指定阶段**：用户明确指定 处理阶段时，只执行该阶段。使用已取得且验证为有效的前置结果；如果缺少必要前置结果，说明缺项并停止，不擅自补跑其他阶段。
- **模式不明确**：用户只说“开始解释”等且无法判断是整套还是逐步执行时，先询问执行模式，不启动专业工具。

含水饱和度与流体识别作为一个阶段，先后调用 `calculate_sw` 和 `identify_fluid`；逐步执行时，两项都完成后再暂停。

## 操作上下文与结果记录

1. 从服务端上下文或 `get_well_data` 返回值取得当前井和资料版本。
2. 使用用户明确指定的顶底深，或用户要求使用的当前范围。没有明确范围时先澄清，不要求用户去工作台点选。
3. 用户明确要求全井解释时，通过 `get_well_data` 取得实际顶底深。读取全井概要不等于用户授权全井解释。
4. 完整流程的 资料准备步骤调用 `get_well_data` 并传入目标顶底深。后续工具传入相同的 `well_id`、`dataset_revision`、`top_depth_m` 和 `bottom_depth_m`。当前工具深度使用 MD，m。
5. 在内部记录工具实际返回的状态、结果引用、上下文和结果正文。后续调用的 `input_result_ids` 传入本次流程此前已取得且可用的结果引用，不编造引用；这些机器字段只用于流程控制，不原样展示给用户。

## 阶段顺序

| 顺序 | 处理内容 | 调用工具 | 继续条件 |
|---|---|---|---|
| 1 | 资料准备 | `get_well_data` | 井、版本及目标范围明确，资料读取成功 |
| 2 | 资料完整性检查 | `check_data_completeness` | 必需资料满足要求，未被阻断 |
| 3 | 曲线质量检查 | `check_curve_quality` | 质量检查允许继续 |
| 4 | 岩性识别 | `identify_lithology` | 岩性结果可用 |
| 5 | 物性评价 | `evaluate_petrophysics` | 物性结果可用 |
| 6 | 含水饱和度与流体识别 | 先 `calculate_sw`，再 `identify_fluid` | 两项结果均可用 |
| 7 | 层分类 | `classify_layer` | 分类结果可用 |
| 8 | 层段整理 | `merge_intervals` | 层段结果可用，保留返回的层界与厚度依据 |
| 9 | 解释验证 | `validate_interpretation` | 验证结果允许继续，无未解决复核事项 |
| 10 | 报告前检查 | `prepare_report` | 实际前置结果齐全，结构检查通过 |

按阶段依次执行。存在输入依赖的调用不得并行。整套流程模式下，满足继续条件后自动进入下一阶段；逐步执行模式下，即使可以继续也必须在当前阶段结束后暂停。含水饱和度与流体识别阶段是一个阶段中的两次工具调用。

已有结果必须属于当前用户和会话，且井、资料版本、范围及实际采用参数与本次任务匹配。参数变更会影响本步及实际依赖它的后续结果；历史结果可查看，但过期结果不能作为可用前置依据。确认结果仍适用后，可以作为对应阶段的依据；保持各阶段依赖顺序。

## 停止与汇总

- `SUCCESS` 表示本项业务处理成功，不代表整个解释完成。
- `WARNING` 需要保留告警；只有返回的 `can_continue` 为 true 时才执行下一项。
- `ERROR`、`FAILED`、`BLOCKED`、`UNKNOWN` 或 `REVIEW_REQUIRED` 时停止后续依赖操作。说明停止阶段、原因和待解决事项。紧急交付或用户要求继续不能替代缺失资料和专业复核。
- 报告前检查使用实际 `input_result_ids` 检查完成情况。它不接受模型自行声明的“已完成阶段”，也不生成报告正文。
- 汇总各阶段实际完成情况、主要结果、依据、告警和复核事项。只有报告前检查通过，才能说明完整流程已完成；结构检查通过不等于专业验收通过。

面向用户汇报时，只使用用户能理解的阶段名称，不展示 `W01` 至 `W10` 等流程编号。将状态码和继续条件翻译成自然中文，例如“曲线质量检查已完成，可以继续岩性识别”或“检查发现缺少必需曲线，流程暂停，请补充资料”。不要展示 `SUCCESS`、`can_continue`、`result_id`、UUID 等原始字段或内部标识，也不要把工具 JSON 拼成结果表。用户明确要求原始技术信息时，才解释字段含义；后续工具调用仍须在内部使用真实结果引用。

完整流程执行期间，阶段与阶段之间要向用户提供简短的测井专业进展说明。调用本阶段工具前，说明本阶段要检查或解释的内容；收到结果后，先概括实际发现、其测井意义、告警及继续依据，再执行下一阶段。说明应包含有用的专业信息，例如哪些曲线质量问题会影响解释、岩性或物性结果如何支持后续判断、层段整理保留了什么依据。具体内容必须来自实际资料和工具结果，不得编造曲线表现、数值、地质结论或尚未完成的结果。避免只显示“思考中”、只报工具名，或连续调用完所有工具后才一次性给出全部说明；也避免逐步重复同一信息。
